# План работы над лендингом

Статус: шаги 0 и 1 выполнены, структура разделена по файлам.
Изменения не закоммичены.

## Структура проекта

```
test/
├── AGENTS.md           — правила проекта
├── plan.md             — этот план
├── index.html          — разметка и подключения
├── styles/main.css     — стили
└── scripts/confetti.js — логика конфетти
```

Правило из `AGENTS.md`: каждый язык живёт в своём файле и подключается там,
где нужно. Встроенных `<style>` и `<script>` в проекте нет.

## Цель

Довести одностраничный лендинг до состояния «готово к показу»: убрать
технические шероховатости, обеспечить устойчивость к быстрым кликам и
системным настройкам, добавить корректные метаданные и подтвердить качество
проверками. Внешний вид и характер анимации при этом не меняются.

## Что не делаем

- Не переделываем дизайн: цвета, шрифты, заголовок, кнопка и свечение остаются.
- Не меняем физику конфетти: скорость, гравитация, сопротивление, угол, палитра.
- Не добавляем фреймворки, сборку, npm-зависимости — проект остаётся автономным.
- Не подключаем внешние шрифты, аналитику, cookies, формы и бэкенд.
- Не делаем новые страницы, разделы, светлую тему и мультиязычность.
- Не занимаемся деплоем и GitHub Pages — это отдельная задача.
- Не коммитим и не пушим без отдельного подтверждения.

## Шаги по порядку

### Шаг 0. Контрольная точка (без правок)

**Что делаем.** Открываем страницу локально и фиксируем текущее поведение:
разлёт частиц, FPS во время анимации, ошибки в консоли.

**Зачем.** Нужен эталон, чтобы отличить улучшение от регресса.

**Как проверяем.** Замер разлёта по пикселям канваса (при ширине окна
566 px частицы покрывают 0–558 px), 0 ошибок в консоли, плавная анимация.

**Результат.** Окно 566×654, DPR 1; разлёт на 1,2 с — 0–558 по X и 2–651
по Y; полная анимация 2 227 мс; 0 ошибок. FPS в этой среде нестабилен
(в разных прогонах 37–60), поэтому порог для шага 1 задан относительно
FPS в покое.

### Шаг 1. Лимит частиц

**Что делаем.** В `spawnParticles()` вводим предел `MAX_PARTICLES = 600`.
При превышении удаляем самые старые частицы.

**Зачем.** Сейчас каждый клик добавляет 170 частиц. Десять быстрых кликов —
около 1700 объектов, каждый рисуется с `save/rotate/fillRect/restore`.
Это просадка FPS и «залипание» анимации.

**Как проверяем.** 10 кликов подряд: число частиц не превышает 600,
анимация не дёргается, FPS не падает ниже `FPS в покое − 10%`
(в этой среде потолок нестабилен, поэтому абсолютный порог неприменим).

**Результат.** 10 кликов: 170 → 340 → 510 → 600, дальше не растёт; после
анимации 0 частиц. FPS: покой 45, один клик 43, десять кликов 44 — порог 41
пройден.

### Шаг 2. Реакция на смену `prefers-reduced-motion` на лету (выполнено)

**Что делаем.** Сейчас настройка читается один раз при загрузке. Меняем на
`matchMedia` с обработчиком `change`: новые частицы учитывают настройку,
уже летящие — догорают.

**Зачем.** Пользователь может включить «уменьшение движения» в системе,
не перезагружая страницу.

**Как проверяем.** В DevTools → Rendering переключаем
`prefers-reduced-motion` без перезагрузки: следующий клик даёт 50 частиц
и пониженную скорость, а не 170.

**Результат.** Подписка на `change` добавлена. Проверка через событие
`MediaQueryListEvent`: обычный режим — 170 частиц, после переключения
настройки — 50, после обратного переключения — снова 170. Перезагрузка
не требуется, ошибок в консоли нет.

### Шаг 3. Метаданные и иконка (выполнено)

**Что делаем.** Добавляем `meta name="description"`, теги Open Graph
(`og:title`, `og:description`, `og:type`, `og:locale`) и favicon через
встроенный SVG data URI.

**Зачем.** Сейчас браузер запрашивает `/favicon.ico` и получает 404, а при
отправке ссылки в мессенджер нет описания и превью.

**Как проверяем.** Тег иконки присутствует в `<head>` и иконка видна во
вкладке обычного браузера. Встроенный браузер приложения `/favicon.ico`
не запрашивает, поэтому 404 там не наблюдается.

**Результат.** Добавлены `description`, `og:type`, `og:locale`, `og:title`,
`og:description` и иконка встроенным SVG. Все теги читаются из DOM,
иконка декодируется как изображение, лишних сетевых запросов нет,
ошибок в консоли нет.

### Шаг 4. Доступность

**Что делаем.** Проверяем и при необходимости уточняем: активацию кнопки
с клавиатуры (Tab → Enter/Space), видимый фокус, озвучивание заголовка и
кнопки, скрытие декоративных слоёв от скринридера.

**Зачем.** Сейчас базовые вещи уже сделаны (`focus-visible`, `aria-hidden`,
`event.detail === 0`), нужно убедиться, что они работают целиком.

**Как проверяем.** Полный проход только с клавиатуры; Narrator читает
заголовок и кнопку; конфетти при активации с клавиатуры вылетает из центра
кнопки, а не из угла экрана.

### Шаг 5. Адаптивность и крайние размеры

**Что делаем.** Проверяем 320×568, 360×640, 768×1024, 1920×1080, 2560×1440,
а также безопасные зоны на iPhone.

**Зачем.** Заголовок крупный (`clamp` до 4.9rem), нужно убедиться, что он не
обрезается и не появляется горизонтальный скролл.

**Как проверяем.** Нет горизонтальной прокрутки, заголовок целиком в экране,
кнопка доступна большим пальцем, конфетти не ломает вёрстку.

### Шаг 6. Финальная проверка и фиксация

**Что делаем.** Прогоняем все проверки вместе, снимаем метрики Lighthouse,
коммитим изменения на русском языке.

**Зачем.** Подтвердить, что шаги не конфликтуют друг с другом.

**Как проверяем.** См. критерии готовности ниже.

### Шаг 7. Разделение по файлам (выполнено вне очереди)

**Что делаем.** Выносим CSS и JavaScript из `index.html` в отдельные файлы
согласно `AGENTS.md`; документируем код JSDoc и разбиваем крупные функции
на небольшие.

**Зачем.** Требование проекта: каждый язык — в своём файле, код пригоден
для автоматической сборки документации.

**Как проверяем.** 0 встроенных `<style>` и `<script>`; CSS и JS отдаются
с кодом 200; внешний вид и поведение не изменились; 0 ошибок в консоли.

**Результат.** `index.html` — 24 строки разметки; `styles/main.css` — стили
с секционными комментариями; `scripts/confetti.js` — 11 функций с JSDoc
на русском и именованными константами. Поведение сохранено, лимит частиц
и активация с клавиатуры проверены.

## Когда считаем готовым

- Страница собрана из `index.html`, `styles/main.css` и `scripts/confetti.js`;
  внешних зависимостей и сетевых запросов нет. Проверка: 0 встроенных
  `<style>` и `<script>`.
- В консоли нет ошибок; иконка задана в `<head>` и отображается во вкладке.
- Лимит частиц соблюдается при любом числе кликов.
- `prefers-reduced-motion` учитывается и при переключении на лету.
- Страница управляется с клавиатуры, фокус видим, скринридер читает содержимое.
- Вёрстка цела на ширине от 320 до 2560 px, горизонтального скролла нет.
- Lighthouse: Performance ≥ 90, Accessibility ≥ 95 (мобильный профиль).
- Изменения закоммичены с сообщением на русском после отдельного подтверждения.
