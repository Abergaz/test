## Когда применять

Когда пользователь просит закоммитить изменения.

## Порядок

1. Показать, что изменится: `git status --short` и `git diff --stat`.
2. Проверить, что в коммит не попадают служебные файлы:
   - временные стенды и тестовые страницы;
   - отладочные хуки вида `window.__confettiCount`;
   - файлы с текстом сообщения коммита;
   - `.DS_Store`, `node_modules`, логи.
3. Сверить изменения с `AGENTS.md`:
   - комментарии и документация на русском;
   - у функций есть JSDoc;
   - CSS и JavaScript лежат в своих файлах, без встроенных `<style>`
     и `<script>`;
   - функции небольшие и с понятными именами.
4. Составить сообщение на русском языке:
   - первая строка до 72 символов, в повелительном наклонении;
   - пустая строка;
   - тело: что изменилось и зачем, без пересказа кода строка за строкой.
5. Показать сообщение пользователю и дождаться подтверждения.
6. Добавить в индекс только нужные файлы поимённо, без `git add -A`.
7. Закоммитить через `git commit -F` с временным файлом сообщения,
   затем удалить временный файл.
8. Пуш выполнять только отдельной командой после отдельного подтверждения.

## Запрещено

- Коммитить без подтверждения пользователя.
- Использовать `git add -A` или `git add .` без просмотра списка файлов.
- Писать сообщения коммитов на английском.
- Пушить вместе с коммитом, если об этом не просили отдельно.

## Отчёт

Хеш, заголовок коммита, число файлов и строк, состояние ветки
относительно `origin`.
